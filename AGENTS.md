# Правила разработки (AshCRM Notify для Windows)

Приложение разрабатывается **отдельно от CRM**. Всё, что ему нужно знать о CRM, — в
[`docs/NOTIFY_CONTRACT.md`](docs/NOTIFY_CONTRACT.md): вход, REST, WebSocket, карточки, коды ошибок, тайминги,
требования безопасности. Код CRM (`crm-ashbyte`) читать не нужно; если чего-то в контракте не хватает —
это вопрос к владельцу CRM, а не догадка по коду.

## Документы
* [`docs/NOTIFY_CONTRACT.md`](docs/NOTIFY_CONTRACT.md) — контракт с CRM (копия; оригинал —
  `crm-ashbyte/docs/NOTIFY_CONTRACT.md`). **Здесь его не редактировать**: новая версия приходит из CRM целиком.
* [`docs/APP_SPEC.md`](docs/APP_SPEC.md) — ТЗ приложения и принятые решения.
* [`README.md`](README.md) — как устроено, сборка, выпуск.
Документация и общение — на русском.

## Новая версия контракта
1. Положить новый `NOTIFY_CONTRACT.md` из CRM в `docs/` без правок.
2. По §11 «История версий» понять, что изменилось.
3. **Минорная** версия (1.0 → 1.1): старое продолжает работать; новые поля/виды/кадры добавить по желанию.
   **Мажорная** (→ 2.0): переделать затронутое, иначе CRM скажет «обновите приложение».
4. Поднять `app.Contract` (`internal/app/app.go`) до версии файла — тест `TestContractVersion` следит, чтобы
   они совпадали. Поправить поддельную CRM в `internal/stream/stream_test.go`, если поменялись кадры.
5. Проверить против CRM с этой версией контракта: `make stand-test SERVER=… PASSWORD=…`.

## Технологии
* Windows 10/11, Go без cgo, Win32/GDI напрямую (`internal/winui`); логика (`internal/app`, `queue`, `stream`,
  `login`, `api`) не зависит от ОС и тестируется на любой системе.
* Связь — одно WebSocket-соединение, без опроса API по таймеру (контракт §4–5).

## Безопасность (не ослаблять без решения владельца)
* Ключ сессии — только под DPAPI (`internal/platform`), ключи и коды не писать в журналы и сообщения.
* Вход — только loopback `127.0.0.1` + PKCE + сверка `state` (контракт §2, §6).
* `http://` — только для локальной сети (`app.NormalizeServer`).
* В браузере открывать только `<портал> + путь` карточки (`app.open`), не абсолютные адреса от сервера.
* Обновления — только из релизов этого репозитория, с проверкой SHA-256 (`internal/app/update.go`).

## Версии, Git, выпуск
* Версия — только в `VERSION`; каждая правка поднимает последнюю цифру и добавляет запись в `CHANGELOG.md`.
* Работа в ветках, в `main` — через PR (проверки — `.github/workflows/check.yml`).
* Выпуск — тег `vX.Y.Z`, равный `VERSION` (`.github/workflows/release.yml`); установленные приложения
  обновятся сами. Выпуск делает владелец.
* Секреты, пароли, ключи, адреса внутренних стендов — не коммитить (репозиторий публичный).

## Проверки
* `make test` (с `-race`), `make vet` (обе сборки), `make stand-test SERVER=… PASSWORD=…` — весь клиент против
  работающей CRM (тестовые учётные записи, сообщения только между ними).
* Окна Windows проверяются руками на Windows: трей, карточки, окно адреса портала, окно настроек, звук, автозапуск, обновление.
