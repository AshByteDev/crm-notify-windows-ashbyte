# ТЗ для CRM: карточка разговора с клиентом в приложении уведомлений

> **Выполнено:** CRM 0.0.66, контракт 1.4, приложение 0.0.15. Отличия от предложения: «Написать в …» — только
> мессенджеры, где клиент уже известен; номер при звонке CRM сама не проверяет (лимит проверок и риск бана) — кнопка
> «Проверить мессенджеры» открывает карточку клиента с проверкой (решение владельца 06.11). «Карточка клиента» нового
> номера — его карточка «из звонка» (`/contacts/<id>`), страницы создания нет. В снимок входит только «Разговор»,
> «Звонит» — нет (предел 3 минуты у него остаётся).

Документ для `crm-ashbyte`. Приложение AshCRM Notify (с 0.0.14) уже держит карточки до действия сотрудника; карточка
«Звонит» (`ring-…`, контракт 1.3) сейчас уходит при ответе. Нужно, чтобы она оставалась на весь разговор и давала
действия с этим номером. Это новые поля и новое поведение, поэтому нужна версия контракта **1.4**; приложение сделает
свою часть, когда она придёт (`AGENTS.md`, «Новая версия контракта»).

## Что видит сотрудник (решение владельца 06.11)
1. Звонит клиент — карточка «Звонит: Имя - Организация», как сейчас.
2. Сотрудник ответил — карточка **не уходит**, а становится «Разговор: Имя - Организация» и висит весь разговор.
   У тех, кому звонок тоже приходил, но кто не ответил, карточка уходит, как сейчас.
3. На карточке действия:
   * **«Пропустить»** — убрать карточку только с этого компьютера. На звонок не влияет, CRM ничего не сообщается.
   * **«Карточка клиента»** — открыть карточку клиента с этим номером, а если клиента нет — создать её с номером.
   * **«Написать»** — открыть диалог с этим номером в мессенджере. CRM сначала проверяет, в каких мессенджерах есть
     номер. Основной мессенджер — кнопкой, остальные найденные — в меню рядом с ней. Если не найдено ни одного,
     кнопки нет.
4. Разговор закончился — карточка уходит сама (`notify.clear`), как сейчас при конце звонка.

## Что нужно от CRM
1. **Состояние звонка.** После ответа этому сотруднику прислать `notify.card` с тем же ключом `ring-<call_id>` и
   новым состоянием вместо `notify.clear`. Конец разговора — `notify.clear`. Обновление карточки без нового
   сообщения звука не даёт (`count` не растёт).
2. **Новые поля карточки** (предложение, окончательный вид — за CRM):
   ```json
   {"key": "ring-…", "kind": "call", "title": "Разговор: Пётр - ООО Ромашка", "body": "+7 900 000-00-00 → Продажи",
    "url": "/c/<chat_id>", "sound": "client", "at": "…",
    "call": {"state": "talking"},
    "actions": [
      {"id": "client",   "title": "Карточка клиента",     "url": "/clients/<id>"},
      {"id": "message",  "title": "Написать в WhatsApp",  "url": "/c/<chat_id>", "primary": true},
      {"id": "message",  "title": "Написать в Telegram",  "url": "/c/<chat_id>"}
    ]}
   ```
   * `call.state`: `ringing` — звонит, `talking` — идёт разговор у этого сотрудника.
   * `actions` — готовые действия, которые приложение показывает как есть, не зная мессенджеров. `url` — **путь** в
     CRM, как у карточки: приложение открывает только `<CRM> + url` (контракт §6). Для «Карточки клиента» без клиента —
     путь страницы, которая создаёт клиента с этим номером или предлагает это (например `/clients/new?phone=…`).
     Создавать клиента молча при каждом звонке не нужно: только по нажатию.
   * `primary: true` — основной мессенджер: у клиента, если он выбран, иначе по правилу компании. Порядок массива —
     порядок в меню.
3. **Проверка мессенджеров** может быть медленной. Тогда сначала прислать карточку без `message`, а когда проверка
   закончится — ту же карточку с ними. Приложение заменит её на месте без звука.
4. **Звонок в снимке.** Разговор может идти дольше 3 минут, а приложение сейчас держит звонок не дольше 3 минут: на
   случай, если `notify.clear` потерялся при обрыве связи. Предложение: идущий звонок этого сотрудника (`ringing` и
   `talking`) входит в снимок и в `notify.sync`. Тогда после переподключения приложение само уберёт закончившийся
   звонок, и ограничение по времени станет не нужно.
5. **Без изменений:** клиент 1.3 должен продолжать работать. Незнакомые поля он пропускает и показывает «Разговор: …»
   как обычную карточку звонка.

## Что сделает приложение после контракта 1.4
* Карточка разговора — выше обычной: заголовок, номер, ниже кнопки словами «Пропустить», «Карточка клиента»,
  «Написать в …» и «▾» с остальными мессенджерами.
* Кнопки открывают `<CRM> + url` действия, карточка остаётся до конца разговора.
* Звонок, пропавший из снимка, убирается; ограничение 3 минуты снимается, если CRM примет пункт 4.

## Проверка
1. Звонок, сотрудник ответил: карточка «Разговор: …» висит весь разговор, у остальных ушла при ответе.
2. «Пропустить» убирает карточку только здесь, звонок идёт.
3. «Карточка клиента» открывает клиента; для нового номера — страницу создания с номером.
4. Номер есть в двух мессенджерах: кнопка основного, второй в меню; оба открывают диалог с этим номером.
5. Номера нет ни в одном мессенджере: кнопки «Написать» нет.
6. Разговор 10 минут: карточка не пропадает. Конец разговора — карточка уходит.
7. Обрыв связи во время разговора, звонок закончился, связь вернулась: карточки нет.
