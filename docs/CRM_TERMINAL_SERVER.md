# ТЗ для CRM: приложение уведомлений на терминальном сервере

Приложение AshCRM Notify с версии 0.0.9 работает на терминальном сервере Windows: на одном сервере запущено около 30
копий, по одной в сессии каждого сотрудника. Документ для `crm-ashbyte`. Если поведение CRM изменится, новая версия
контракта приходит в приложение обычным порядком (`AGENTS.md`, «Новая версия контракта»).

## Что изменилось в приложении
* `device` при входе теперь `<имя компьютера> / <пользователь Windows>`, например `TS01 / ivanov`. Формат контракта не
  меняется: это строка, CRM обрезает её до 60 символов.
* Когда сотрудник закрывает удалённый рабочий стол, не выходя из Windows, приложение закрывает WebSocket. Когда он
  возвращается, приложение подключается заново и получает снимок.

## Что проверить и, если нужно, изменить
1. **Сессии разных сотрудников на одном компьютере не должны мешать друг другу.** Контракт говорит «одна сессия на
   компьютер» (§11), а код 4001 — «повторное подключение того же ПК» (§4.4). Ключом должна быть пара «сотрудник +
   устройство». Вход сотрудника А с `TS01` не должен завершать сессию сотрудника Б с `TS01`.
   Проверка: два тестовых сотрудника входят с одного компьютера, оба получают уведомления, кода 4001 нет.
2. **Повторный вход того же сотрудника** с того же устройства по-прежнему заменяет его прежнюю сессию. Проверить, что
   замена работает с новым значением `device`. Прежние сессии с `device` без пользователя (`TS01`) останутся в «Моих
   устройствах» до истечения или ручного завершения; отдельной миграции не требуется.
3. **«Мои устройства» и аудит** показывают `device` целиком: `TS01 / ivanov` должно помещаться в строку интерфейса.
4. **Веб-пуш после отключения.** Закрытие сокета приложением должно сразу снимать признак подключённого приложения
   (`Hub.HasDesktop`), чтобы `desktop_mutes_browser` больше не глушил веб-пуш в браузерах.
   Проверка: сотрудник с включённой настройкой закрывает приложение, пуш приходит в браузер.

## Как оформить результат
Если правки потребовались, описать их в `NOTIFY_CONTRACT.md` новой минорной версией: заменить формулировку §11 на
«одна сессия на сотрудника и устройство» и уточнить код 4001 в §4.4. Если CRM уже работает так, достаточно поправить
формулировки.

## Вне этого ТЗ
Раздача `.exe` через CRM пока не нужна: обновления идут из папки администратора.
