# ТЗ для CRM: быстрый ответ из карточки уведомления

> **Выполнено:** CRM 0.2.8, контракт **1.10** (§3.4, §4, §5.8), приложение 0.0.21. Номер 1.9 заняли поля телефона
> Android. Отличия от ТЗ: файл загружается в существующий `POST /api/v1/uploads` (ответ `201`, нужен `id`), а не в
> новый путь; карточки «Ожидают» с `takes` приходят только оператору на смене.

Документ для `crm-ashbyte`. Нужны новые поля карточки, новый кадр и одна точка REST, поэтому нужна версия контракта
**1.9** (минорная: старые клиенты работают без правок). Приложение сделает свою часть, когда она придёт (`AGENTS.md`,
«Новая версия контракта»).

## Зачем (решения владельца 11.11)
Чтобы ответить на сообщение, сотрудник сейчас идёт в браузер, и каждый клик по уведомлению открывает новую вкладку.
Шаг 1 — ответ прямо в карточке: текст и файлы, как во всплывающих уведомлениях Windows и macOS. Историю переписки
показывать не нужно.

Решения владельца:
1. Ключ приложения получает право **писать**, а не только читать уведомления.
2. Беседы из «Ожидают» тоже можно брать ответом: карточка ярко помечает, что это новая беседа, и ответ **берёт её на
   сотрудника**.
3. Текст и файлы, без истории.
4. В беседе с клиентом важно видеть, кто написал: **клиент** или **сотрудник во внутренней переписке**. При ответе
   можно выбрать: **клиенту** или **внутри беседы** (клиент не увидит).

## Что видит сотрудник
1. Пришла карточка сообщения: личный чат, группа, чат задачи или встречи, своя беседа с клиентом, беседа из «Ожидают».
2. В беседе с клиентом карточка показывает, чьё сообщение: от клиента или внутренняя заметка коллеги («Иван
   (внутри): …»), у внутренней — свой цвет полосы и значок.
3. У беседы из «Ожидают» яркая метка «Новая беседа», а на кнопке ответа подпись «ответ возьмёт беседу».
4. «Ответить» раскрывает поле ввода. В беседе с клиентом над полем переключатель «Клиенту в WhatsApp» / «Внутри
   беседы». По умолчанию выбран тот же адресат, от которого пришло сообщение: ответ на сообщение клиента — клиенту,
   на внутреннюю заметку — внутрь.
5. Скрепка или перетаскивание файла в карточку — вложения, списком под полем, у каждого крестик.
6. Enter — отправить, Shift+Enter — новая строка, Esc — отмена. Пока поле открыто, карточку не вытесняют новые и не
   убирает «Скрыть все». Новое сообщение в тот же чат обновляет текст над полем, набранное не теряется.
7. Отправлено: карточка уходит, чат прочитан на всех устройствах. Не отправлено: текст и файлы остаются, под полем —
   причина словами из ответа CRM, можно повторить.

## Что нужно от CRM

### 1. Поля карточки
* **`from`** — у сообщений беседы с клиентом: `"client"` — написал клиент, `"staff"` — внутренняя переписка
  сотрудников в беседе. В других чатах поля нет.
* **`reply`** — на карточку можно ответить. Есть только там, где сотрудник может ответить прямо сейчас с теми же
  правами, что и в CRM. Нет поля — нет кнопки.
  ```json
  {"key": "chat-0193…", "kind": "mine", "title": "Пётр - ООО Ромашка", "body": "Когда будет счёт?",
   "url": "/my/0193…", "count": 1, "sound": "client", "at": "…", "from": "client",
   "reply": {"modes": [{"id": "client", "title": "Клиенту в WhatsApp"},
                       {"id": "internal", "title": "Внутри беседы"}],
             "files": {"max_mb": 20, "max_count": 10}}}
  ```
  * `modes` — куда можно ответить, первым — что выбрать по умолчанию (по правилу пункта 4 выше). В личном чате,
    группе, чате задачи — один режим `{"id": "chat", "title": "Ответ Марии"}` / «Ответ в группу «Продажи»»;
    переключатель тогда не показывается. Незнакомый `id` приложение показывает как есть по `title`.
  * `takes: true` — у беседы из «Ожидают»: ответ возьмёт беседу на сотрудника. Приложение ставит яркую метку.
  * `files` — можно прикладывать файлы, с ограничениями CRM. Нет поля — без скрепки.
* Где есть `reply`: `chat-` — личные чаты, группы, чаты задач и встреч, свои беседы с клиентами; `queue-` — беседы из
  «Ожидают» (с `takes`). Без `alert-`, звонков, задач, встреч.

### 2. Загрузка файла — REST
`POST /api/v1/desktop/files` (`Authorization: Bearer <access>`, `multipart/form-data`, поле `file`) →
`200 {"file_id": "uuid", "name": "…", "size": int}`. Путь — на выбор CRM. Сейчас ключ приложения в REST открывает
только `GET /me` и `POST /auth/logout` (§3.4): сюда добавляется эта точка. Больше предела или запрещённый тип —
`validation` с `message`. Загруженный и не отправленный файл CRM удаляет сама, например через сутки.

### 3. Кадр `notify.reply` (запрос)
`{"key": "chat-…", "mode": "client", "text": "…", "files": ["<file_id>"], "client_id": "<uuid>"}` →
`{"ok": true}`.
* Сообщение уходит от имени сотрудника, как если бы он написал его в CRM. `client` — клиенту в канал, который
  назван в `title` режима; `internal` — внутренняя заметка в беседе; `chat` — в чат.
* `queue-` с `takes`: беседа сначала берётся на сотрудника, затем уходит ответ. Беседу уже взял другой — `conflict`
  с `message`, ничего не отправлено.
* Затем чат читается до последнего сообщения, как `notify.read`: строки колокольчика, `notify.clear` и
  `notify.sync` на все устройства. Взятая беседа уходит из «Ожидают» у всех, как сейчас.
* `client_id` — ключ повтора: при обрыве связи приложение отправит тот же запрос ещё раз, второго сообщения быть не
  должно.
* `text` — обычный текст, без разметки; может быть пустым, если есть файлы. Ни текста, ни файлов или текст длиннее
  предела CRM — `validation`.
* Нельзя ответить (нет прав, чат закрыт, режим недоступен, например клиенту в канал больше нельзя писать) —
  `forbidden` или `conflict` с `message` для человека: приложение покажет его как есть.

### 4. Права ключа приложения
Ключ приложения (сессия вида `desktop`) получает право писать сообщения: кадр `notify.reply` и загрузка файла. Всё
прочее — как сейчас. Отправленное из приложения не делает сотрудника «в сети».

### 5. Без изменений
Клиент 1.8 не знает `from` и `reply` и показывает карточку как раньше.

## Что сделает приложение после контракта 1.9
* Метка «внутри» у внутренних сообщений беседы, яркая метка «Новая беседа» у `takes`.
* «Ответить» на карточке с `reply`: поле в карточке, переключатель режимов, скрепка и перетаскивание файлов.
  Карточку, где пишут, не убирают ни новые карточки, ни «Скрыть все».
* Файлы загружаются заранее, при выборе; `notify.reply` уходит, когда все загружены. При обрыве — повтор после
  переподключения тем же `client_id`.
* Текст ответа и имена файлов не пишутся в журнал `notify.log`, как и ключи.

## Проверка
1. Личное сообщение → «Ответить» → текст → Enter: сообщение в чате от сотрудника, карточка ушла везде, в колокольчике
   строки нет.
2. Сообщение клиента в своей беседе: переключатель стоит на «Клиенту в …», ответ ушёл клиенту в этот канал.
3. Внутренняя заметка коллеги в беседе: карточка помечена «внутри», переключатель — на «Внутри беседы», клиент ответ не
   получил.
4. Беседа из «Ожидают»: яркая метка, ответ взял беседу на сотрудника и ушёл клиенту. Если её успел взять другой —
   отказ словами, ничего не отправлено.
5. Два файла и текст: в чате одно сообщение с двумя вложениями. Файл больше предела — отказ при выборе.
6. Связь оборвалась на отправке: после переподключения сообщение одно, не два.
7. Звонок, задача, тревога: кнопки «Ответить» нет.
