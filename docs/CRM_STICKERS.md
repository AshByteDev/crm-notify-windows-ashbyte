# ТЗ для CRM: стикеры в карточке уведомления

Документ для `crm-ashbyte`. Нужны новое поле карточки и одна точка REST для ключа приложения, поэтому нужна следующая
минорная версия контракта (**1.11**, если номер свободен; старые клиенты работают без правок). Приложение сделает свою
часть, когда она придёт (`AGENTS.md`, «Новая версия контракта»).

## Зачем (решения владельца 11.11)
CRM умеет отправлять и принимать стикеры (`docs/OUTBOUND_ATTACHMENTS.md`, «Стикеры»). Сейчас в карточке приложения
только текст `body`, и стикер в уведомлении не виден. Нужно показывать сам стикер.

Решения владельца:
1. В карточке приходит не картинка, а **код, хэш и путь** к картинке. Приложение хранит стикеры у себя и показывает
   уже скачанный сразу, без обращения к CRM.
2. Хранилище **общее для всех сотрудников компьютера**: на терминальном сервере каждый стикер скачивается один раз на
   сервер, а не на каждого из 30 сотрудников.
3. Одинаково для **наших стикеров** (наборы CRM) и **чужих**, которые прислал клиент.
4. Стикер показывается **неподвижным** — первым кадром. Анимацию не показываем.
5. Наборы целиком при подключении **не скачиваются**. Понадобятся, когда дойдём до отправки стикеров из быстрого
   ответа, — это отдельное ТЗ.

## Что видит сотрудник
1. Пришло сообщение-стикер в чат или беседу: в карточке вместо текста стикер крупно (около 96 px), без «пузыря», как
   в PWA. Заголовок, время и кружки — как у обычной карточки.
2. Стикер уже встречался на этом компьютере — он виден сразу.
3. Ещё не встречался — карточка приходит сразу со словом «Стикер», картинка появляется, как только скачается.
4. Картинки ещё нет у CRM (коннектор не отдал файл) или она не скачалась — остаётся слово «Стикер».

## Что нужно от CRM

### 1. Поле карточки `sticker`
У карточки, где последнее сообщение — стикер (`kind: "sticker"` у вложения), с картинкой для показа:
```json
{"key": "chat-0193…", "kind": "mine", "title": "Пётр - ООО Ромашка", "body": "Стикер", "url": "/my/0193…",
 "count": 1, "sound": "client", "at": "…", "from": "client",
 "sticker": {"code": "ashbyte-cats/12",
             "hash": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
             "url": "/api/v1/desktop/stickers/9f86d081….png"}}
```
* `code` — постоянный код стикера. Наш стикер — как в CRM, `"<pack>/<id>"` (поле `sticker` вложения). Чужой — код,
  который не меняется, когда клиент присылает тот же стикер ещё раз (например, по SHA-256 исходного файла). Нужен,
  чтобы позже связать карточку с наборами при отправке; приложение пока его только запоминает.
* `hash` — SHA-256 **готовой картинки по `url`** (не исходного файла), 64 знака hex в нижнем регистре. По нему
  приложение хранит файл и проверяет его.
* `url` — **путь** на портале (как `url` карточки: приложение открывает только `<CRM> + url`). У одного `hash` — всегда
  одна и та же картинка.
* `body` остаётся: «Стикер», в группе — «Иван: Стикер». Старые клиенты и приложение без картинки показывают его.
* Где: все карточки сообщений — `chat-` (личные, группы, задачи, встречи, беседы) и `queue-`. Стикер от клиента и от
  коллеги — одинаково.
* Нет поля: последнее сообщение не стикер, или при «Пуш без текста» в CRM — стикер тоже не показывается.
* Картинки ещё нет (`pending_attachments`: `loading`, `failed`, `unavailable`) — `sticker` без `hash` и `url` (или без
  поля). Когда файл пришёл, CRM **присылает карточку заново** (`notify.card` с тем же `key`, без звука, как обновление
  текста), чтобы картинка появилась без нового сообщения.

### 2. Картинка — REST
`GET <url>` (`Authorization: Bearer <access>`) → `200`, `image/png`.
* **Статичная PNG**, первый кадр для анимированных (WebM, Lottie `.tgs` / `.was`), с прозрачным фоном. CRM их уже
  разбирает для PWA; в приложении (Win32 без сторонних библиотек) их не нарисовать.
* Размер: **не больше 192×192** (приложение рисует около 96 px, на экранах 200 % — вдвое больше), сторона не меньше
  64, пропорции стикера. Файл — **не больше 256 КБ**.
* Ключ приложения (сессия `desktop`) получает право читать картинки стикеров. Только их: не другие вложения чата.
* Можно отдавать кэширующими заголовками (`Cache-Control: max-age=31536000, immutable`): картинка по пути не меняется.
* Нет такой картинки или нет доступа — `404`; приложение покажет «Стикер».

### 3. Без изменений
Клиент 1.10 не знает `sticker` и показывает `body`, как раньше.

## Что сделает приложение после контракта
* Папка `%ProgramData%\AshCRM Notify\stickers`, общая для всех сотрудников компьютера. Файл называется `<hash>.png`.
* Карточка с `sticker`: есть файл и его SHA-256 совпала с `hash` — рисуем сразу. Нет файла или сумма не совпала (файл
  испорчен или подменён) — скачиваем `<портал> + url`, проверяем сумму, пишем во временный файл и переименовываем,
  рисуем. Два сотрудника, скачавшие один стикер одновременно, ничего не ломают: файл тот же.
* Подмена файла руками ни на что не влияет: сумма не совпадёт, и стикер скачается заново.
* Пределы: файл до 256 КБ, картинка до 512×512, иначе не рисуем.
* Права папки: сотрудники читают и добавляют файлы. Не внутри папки программы: туда пишут только администратор и
  задача SYSTEM, и это не меняется. Удаляет старые файлы задача SYSTEM раз в сутки (не открывали 30 дней); на обычном
  компьютере — само приложение.
* Папку создать нельзя — стикеры хранятся в памяти до выхода из приложения.
* Фото и другие вложения в эту папку не попадают никогда.
* Ключи, коды стикеров и адреса картинок не пишутся в журнал.

## Проверка
1. Клиент прислал наш стикер в свою беседу: карточка со стикером, звук как у сообщения клиента.
2. Тот же стикер ещё раз: картинка видна сразу, запроса к CRM нет.
3. Второй сотрудник на том же терминальном сервере получил тот же стикер: виден сразу, запроса нет.
4. Клиент прислал чужой стикер из Telegram (анимированный `.tgs`) и из WhatsApp: карточка с первым кадром.
5. Коллега прислал стикер в личный чат и в группу: карточка со стикером, в группе заголовок как у сообщения группы.
6. Файл ещё не пришёл от коннектора: слово «Стикер»; файл пришёл — картинка появилась в той же карточке, без звука.
7. Файл в папке подменён другой картинкой: показан верный стикер, файл скачан заново.
8. «Пуш без текста» в CRM: стикера нет, текст как у обычного сообщения.
9. Ключом приложения нельзя скачать фото или документ из чата.
