# AshCRM Notify для Windows

Приложение в области уведомлений Windows 10/11: показывает уведомления AshCRM своими карточками — о том же, что
приходит веб-пушем (личные, группы, беседы с клиентами, очередь, упоминания, задачи, календарь, тревоги).

* **Обмен с CRM** — [`docs/NOTIFY_CONTRACT.md`](docs/NOTIFY_CONTRACT.md) (версия 1.0): единственное, что нужно
  знать о CRM. Меняется CRM → приходит новая версия файла → приложение дописывается по ней (см. `AGENTS.md`).
* ТЗ и принятые решения — [`docs/APP_SPEC.md`](docs/APP_SPEC.md); правила разработки — [`AGENTS.md`](AGENTS.md).
* Нужна AshCRM 0.0.40 или новее (вход приложения и карточки).

## Как работает
* **Первый запуск** — окно «Адрес портала AshCRM»: тот же адрес, что в браузере (`crm.company.ru`, схема и путь
  не нужны). Приложение проверяет, что там AshCRM с поддержкой приложения (0.0.40+), запоминает адрес; к нему же
  подключение и все ссылки карточек. Сменить — «Сменить портал…» в меню. Одна сборка подходит для любого портала.
* **Вход** — через браузер: «Войти» открывает страницу CRM «Подключить приложение AshCRM для Windows?», код
  возвращается приложению на `127.0.0.1` (RFC 8252 + PKCE). Пароль приложению не передаётся; ключ сессии
  хранится в `%APPDATA%\AshCRM Notify\session.bin`, зашифрованный DPAPI текущего пользователя Windows.
* **Связь** — одно постоянное WebSocket-соединение (`/ws`): при подключении снимок (20 новых карточек), дальше
  события сразу от сервера; без опроса API. Обрыв — переподключение с растущей паузой, после сна компьютера — сразу.
* **Активность** — приложение сообщает CRM, был ли ввод в этой сессии Windows за последнюю минуту, чтобы телефон не
  звонил, пока человек работает в другой программе. Передаётся только «да» или «нет», ни программы, ни содержимое.
* **Карточки** — одна на чат, компактные: время и отправитель, справа значки, ниже две строки сообщения (длиннее —
  обрезается). До трёх на экране, каждая 5 секунд (`notification_seconds` в `config.json`, под мышью ждёт), следующие показываются за ними. Пока есть
  непрочитанные, у края экрана остаётся полоска с их числом: карточки появляются над ней или под ней, если они вверху
  экрана. Клик по полоске открывает список: три последних уведомления, колесо мыши листает, значки работают; закрывается
  повторным кликом или когда мышь ушла. Правый клик — «Открыть AshCRM» и «Прочитать все».
  справа (по умолчанию справа внизу). Там же «Проверить уведомления»: запрос в CRM через сокет, тестовая карточка
  со звуком и имя сотрудника, которому приходят уведомления. Значки: «✓» — прочитано (читает чат в CRM,
  карточка исчезает на всех устройствах; без связи отправится после переподключения), «↗» — открыть в браузере на
  нужном месте, «✕» — убрать только здесь.
* **Трей** — значок (синий — подключено, серый — нет связи/не выполнен вход, оранжевый — «Не беспокоить», красная
  точка — есть уведомления), меню: «Не беспокоить», «Настройки…», «Запускать вместе с Windows», «Проверять обновления», выход.
* Звуки: «клиент» (сообщение клиента, новая беседа) и «прочие»; серия сообщений — один звук. Звук — только у новых
  событий (`notify.card`): снимок при подключении идёт без звука.
* **Обновления** — из релизов этого репозитория: раз в час (выключается в меню, период в `config.json`) и по «Проверить
  обновления». Новая версия — карточка «Доступна версия …» с кнопкой «Обновить»: приложение скачивает файл рядом с собой,
  сверяет SHA-256 из релиза и перезапускается с него (см. «Файлы рядом с приложением»).

## Безопасность
* Пароль приложению не передаётся: вход в браузере, код возвращается на `127.0.0.1` и меняется на ключи только
  вместе с секретом PKCE, который знает лишь это приложение; `state` сверяется.
* Ключ сессии зашифрован DPAPI пользователя Windows; ключ доступа живёт 15 минут, ключ обновления одноразовый
  (повтор украденного завершает сессию). В CRM ключ приложения открывает только поток уведомлений, «кто я» и выход.
* `http://` — только для портала в локальной сети; иначе `https://`.
* Карточки открывают в браузере только страницы своего портала; абсолютные адреса от сервера не открываются.
* Обновление берётся только из релизов этого репозитория: новая версия ложится рядом и запускается лишь при совпадении
  SHA-256. На терминальном сервере в папку приложения пишут только администратор и задача SYSTEM.
* Сессия видна в CRM («Мои устройства», «приложение Windows»); там же её можно завершить — приложение сразу
  отключится. Повторное подключение того же компьютера завершает его прежнюю сессию.
* Без подписи кода (Authenticode): SmartScreen может предупредить при первом запуске.

## Файлы рядом с приложением
Сборка одна. `AshCRM-Notify.exe` всегда сохраняет имя: на него указывают автозапуск и ярлык. При запуске он находит самую
новую версию рядом, запускает её и сразу закрывается. Новая версия ничего не заменяет, а появляется рядом:
```
AshCRM-Notify.exe                   постоянное имя
config.json                         настройки, сверху примеры всех полей
AshCRM-Notify-0.0.11.exe            версия
AshCRM-Notify-0.0.11.exe.sha256     её сумма, файл без верной суммы не запускается
```
* `config.json` читается при запуске и при каждой проверке. Если файла нет, приложение создаёт его после успешной
  проверки портала. Строки с `//` — комментарии.
* `notification_seconds` — сколько секунд показывать уведомление, 5 по умолчанию.
* `update_check_minutes` — как часто искать новую версию, 60 по умолчанию; `0` — только при запуске.
* `version` держит всех на одной версии: вернуть старую можно, указав её здесь. Обновления — только из релизов этого
  репозитория.
* `disabled: true` удаляет приложение из профиля каждого пользователя папки.
* Приложение само хранит две последние версии, закреплённую и работающую, остальные удаляет. Занятый файл удаляется при
  следующем проходе.

## Терминальный сервер
Каждому пользователю нужен свой процесс: служба Windows не может показать значок в чужой сессии. Но файл один, и
сотрудники могут только читать папку. Если писать рядом с собой нельзя, приложение не скачивает обновления, а ждёт, когда
новая версия появится рядом. Скачивает её задача планировщика от имени SYSTEM.

Администратор один раз:
1. Создаёт `C:\Program Files\AshCRM Notify`, кладёт туда `AshCRM-Notify.exe` из релиза и `config.json`:
   ```json
   { "server": "https://crm.company.ru" }
   ```
2. Создаёт задачу в командной строке администратора:
   ```bat
   schtasks /Create /TN "AshCRM Notify Update" /SC HOURLY /RU SYSTEM /F /TR "\"C:\Program Files\AshCRM Notify\AshCRM-Notify.exe\" --fetch-update"
   ```
3. Даёт сотрудникам ссылку на файл. Первый запуск включает автозапуск и ярлык на рабочем столе и просит войти в браузере.

* **Обновление.** Выходит релиз, задача скачивает версию, копии примерно за час перезапускаются с неё без вопросов.
  Остановить обновления — отключить задачу или указать `version`.
* **Удаление.** У одного пользователя — `AshCRM-Notify.exe --uninstall`, у всех — `disabled: true`; папку удаляет
  администратор. Сессия в CRM завершается.
* В меню нет обновлений, а при заданном `server` — смены портала.
* Когда сотрудник закрывает удалённый рабочий стол, не выходя из Windows, приложение отключается от CRM, чтобы
  уведомления дошли в браузер, а при возвращении подключается снова.
* Серверу нужен доступ к github.com. На стороне CRM — [`docs/CRM_TERMINAL_SERVER.md`](docs/CRM_TERMINAL_SERVER.md).

## Сборка и выпуск
Чистый Go без cgo, собирается на любой системе:
```bash
make build                                           # dist/AshCRM-Notify.exe (~8 МБ); SERVER=… лишь подставит адрес в окно
make test                                            # логика (очередь, поток, вход, звуки, иконки)
make vet                                             # обе сборки: эта ОС и Windows
make stand-test SERVER=http://localhost:8780 PASSWORD=…  # весь клиент против работающей CRM
make run SERVER=http://localhost:8780                # консольный режим (не Windows): печатает карточки
```
**Выпуск версии**: поднять `VERSION`, записать `CHANGELOG.md`, влить в `main`, поставить тег `vX.Y.Z` (равный
`VERSION`) и отправить его — GitHub Actions (`.github/workflows/release.yml`) прогонит тесты, соберёт
`AshCRM-Notify.exe` и `.sha256` и опубликует релиз с текстом из `CHANGELOG.md`. Установленные приложения увидят
его при следующей проверке. Проверки на каждый PR — `.github/workflows/check.yml`.

## Структура
* `cmd/crm-notify-windows` — точка входа (`main_windows.go` — трей, `main_other.go` — консольный режим).
* `internal/app` — всё вместе: портал, сессия, поток, очередь, действия, обновления из релизов.
* `internal/queue` — карточки: три на экране, время показа, ожидание, счёт непрочитанных, «Не беспокоить», отложенные «✕».
* `internal/stream` — WebSocket: снимок, `notify.card|clear|sync|activity`, ping, обновление ключа, переподключение.
* `internal/managed` — что лежит рядом с `.exe`: `config.json`, файлы версий, выбор версии, очистка старых.
* `internal/login` — вход через браузер; `internal/api` — HTTP-вызовы CRM.
* `internal/platform` — настройки, DPAPI, браузер, автозапуск, звук, время без ввода (Windows и заглушки для разработки).
* `internal/winui` — Win32/GDI: трей, меню, окна карточек, окно адреса портала, окно настроек (`layout.go` — расчёт положения, тестируется на любой ОС); `internal/sound` — синтез звуков.
