# AshCRM Notify для Windows

Приложение в области уведомлений Windows 10/11: показывает уведомления AshCRM своими карточками — о том же, что
приходит веб-пушем (личные, группы, беседы с клиентами, очередь, упоминания, задачи, календарь, тревоги).

* **Обмен с CRM** — [`docs/NOTIFY_CONTRACT.md`](docs/NOTIFY_CONTRACT.md) (версия 1.0): единственное, что нужно
  знать о CRM. Меняется CRM → приходит новая версия файла → приложение дописывается по ней (см. `AGENTS.md`).
* ТЗ и принятые решения — [`docs/APP_SPEC.md`](docs/APP_SPEC.md); правила разработки — [`AGENTS.md`](AGENTS.md).
* Нужна AshCRM 0.0.40 или новее (вход приложения и карточки).

## Как работает
* **Первый запуск** — окно «Адрес портала AshCRM»: тот же адрес, что в браузере (`crm.company.ru`, схема и путь
  не нужны). Приложение проверяет, что там AshCRM с поддержкой приложения (0.0.40+), запоминает адрес; к нему же
  подключение и все ссылки карточек. Сменить — «Сменить портал…» в меню. Одна сборка подходит для любого портала.
* **Вход** — через браузер: «Войти» открывает страницу CRM «Подключить приложение AshCRM для Windows?», код
  возвращается приложению на `127.0.0.1` (RFC 8252 + PKCE). Пароль приложению не передаётся; ключ сессии
  хранится в `%APPDATA%\AshCRM Notify\session.bin`, зашифрованный DPAPI текущего пользователя Windows.
* **Связь** — одно постоянное WebSocket-соединение (`/ws`): при подключении снимок (20 новых карточек), дальше
  события сразу от сервера; без опроса API. Обрыв — переподключение с растущей паузой, после сна компьютера — сразу.
* **Карточки** — одна на чат («ещё N непрочитанных»), до трёх на экране, остальные ждут; полоса «Ещё N уведомлений —
  открыть AshCRM». Место выбирается в «Настройки…» кликом по картинке монитора: сверху или снизу — слева, по центру,
  справа (по умолчанию справа внизу). Там же «Проверить уведомления»: запрос в CRM через сокет, тестовая карточка
  со звуком и имя сотрудника, которому приходят уведомления. Кнопки: «Открыть» (браузер на нужном месте), «Прочитано» (читает чат в CRM —
  карточка исчезает на всех устройствах; без связи отправится после переподключения), «✕» (убрать только здесь).
* **Трей** — значок (синий — подключено, серый — нет связи/не выполнен вход, оранжевый — «Не беспокоить», красная
  точка — есть уведомления), меню: «Не беспокоить», «Настройки…», «Запускать вместе с Windows», «Проверять обновления», выход.
* Звуки: «клиент» (сообщение клиента, новая беседа) и «прочие»; серия сообщений — один звук. Звук — только у новых
  событий (`notify.card`): снимок при подключении идёт без звука.
* **Обновления** — из релизов этого репозитория: раз в сутки (выключается в меню) и по «Проверить обновления».
  Новая версия — карточка «Доступна версия …» с кнопкой «Обновить»: приложение скачивает `AshCRM-Notify.exe`,
  сверяет SHA-256 из релиза, ставит его на место текущего файла и перезапускается. Если папка приложения закрыта
  на запись (например, `Program Files` без прав администратора), обновление сообщит об этом — скачайте файл со
  страницы релиза.

## Безопасность
* Пароль приложению не передаётся: вход в браузере, код возвращается на `127.0.0.1` и меняется на ключи только
  вместе с секретом PKCE, который знает лишь это приложение; `state` сверяется.
* Ключ сессии зашифрован DPAPI пользователя Windows; ключ доступа живёт 15 минут, ключ обновления одноразовый
  (повтор украденного завершает сессию). В CRM ключ приложения открывает только поток уведомлений, «кто я» и выход.
* `http://` — только для портала в локальной сети; иначе `https://`.
* Карточки открывают в браузере только страницы своего портала; абсолютные адреса от сервера не открываются.
* Обновление скачивается только из релизов этого репозитория и ставится лишь при совпадении SHA-256.
* Сессия видна в CRM («Мои устройства», «приложение Windows»); там же её можно завершить — приложение сразу
  отключится. Повторное подключение того же компьютера завершает его прежнюю сессию.
* Без подписи кода (Authenticode): SmartScreen может предупредить при первом запуске.

## Сборка и выпуск
Чистый Go без cgo, собирается на любой системе:
```bash
make build                                           # dist/AshCRM-Notify.exe (~8 МБ); SERVER=… лишь подставит адрес в окно
make test                                            # логика (очередь, поток, вход, звуки, иконки)
make vet                                             # обе сборки: эта ОС и Windows
make stand-test SERVER=http://localhost:8780 PASSWORD=…  # весь клиент против работающей CRM
make run SERVER=http://localhost:8780                # консольный режим (не Windows): печатает карточки
```
**Выпуск версии**: поднять `VERSION`, записать `CHANGELOG.md`, влить в `main`, поставить тег `vX.Y.Z` (равный
`VERSION`) и отправить его — GitHub Actions (`.github/workflows/release.yml`) прогонит тесты, соберёт
`AshCRM-Notify.exe` и `.sha256` и опубликует релиз с текстом из `CHANGELOG.md`. Установленные приложения увидят
его при следующей проверке. Проверки на каждый PR — `.github/workflows/check.yml`.

## Структура
* `cmd/crm-notify-windows` — точка входа (`main_windows.go` — трей, `main_other.go` — консольный режим).
* `internal/app` — всё вместе: портал, сессия, поток, очередь, действия, обновления из релизов.
* `internal/queue` — карточки: три на экране, ожидание, «Не беспокоить», отложенные «✕».
* `internal/stream` — WebSocket: снимок, `notify.card|clear|sync`, ping, обновление ключа, переподключение.
* `internal/login` — вход через браузер; `internal/api` — HTTP-вызовы CRM.
* `internal/platform` — настройки, DPAPI, браузер, автозапуск, звук (Windows и заглушки для разработки).
* `internal/winui` — Win32/GDI: трей, меню, окна карточек, окно адреса портала, окно настроек (`layout.go` — расчёт положения, тестируется на любой ОС); `internal/sound` — синтез звуков.
